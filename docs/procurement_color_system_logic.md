# 建议下单量与颜色体系汇总逻辑

## 1. 建议下单量

运行日期起只读取未来 4 个自然月的 `预测对比表_SKU` 数据。

- 定制面料：覆盖 T、T+1、T+2 共 3 个月。
- 现货面料：覆盖 T、T+1 共 2 个月。
- 建议下单量：`MAX(0, 覆盖月份预测 - 可售库存 - 本地可用 - FBA在途 - 本地待到货)`。
- 月度建议下单只在覆盖月份内按系统预测占比分摊，采用最大余数法，保证月度合计严格等于建议下单总量。

## 2. 颜色体系

颜色身份使用：

```text
颜色体系 + 颜色代码
```

例如：

```text
A2023:BK
B2024:BK
```

即使裸颜色代码相同，也不会跨体系自动合并。

识别顺序：

1. `lxpm_product_category_snapshot` 中该 SKU 的“颜色体系”精确值。
2. 同 SPU、同颜色代码的已标记 SKU 若只存在一个体系，则继承该体系。
3. 同 SPU 的已标记 SKU 若只存在一个体系，则继承该体系。
4. 仍无法唯一识别则进入“待定”，不与 A2023/B2024 合并。

特殊 SKU：

- `SHORT/LONG/TALL/PETITE` 版型段会跳过后再提取颜色代码。
- PCS 多色套装生成独立 `MULTI[...]` 颜色身份，不强行归入单色。

## 3. 面料预计用量

简版面料汇总按逐 SPU 计算：

```text
预计用量 = Σ(建议下单量 × 单件用量 × 单件损耗)
```

不再使用“所有建议下单量合计 × 最后一个 SPU 的单耗”。

输出的“有效加权单耗”是：

```text
总预计用量 ÷ 建议下单量合计
```

## 4. 面料详细预估

详细预估在建议下单量写库后立即重新生成，再写入飞书。

- T~T+3 优先使用颜色体系级建议下单量。
- 同一颜色身份下的尺码 SKU 按系统预测占比分配，合计严格守恒。
- 建议下单量明确为 0 时保持 0，不再错误回退到系统预测。
- 只有建议下单记录不存在时才回退到系统预测。
- 面料颜色维度使用 `面料 + 颜色体系 + 归并颜色代码` 汇总。

## 5. 面料库存归属

`面料颜色归并对照` 如果已维护“颜色体系”，优先使用：

```text
面料编号 + 颜色体系 + 原始颜色缩写 → 归并颜色缩写
```

没有体系级规则时兼容旧规则：

```text
面料编号 + 原始颜色缩写 → 归并颜色缩写
```

如果同一个面料库存键同时被 A2023/B2024 使用，系统不会把一份库存重复扣给两个体系，而会：

- 库存和待到货暂记 0；
- `库存归属状态` 标记为“跨颜色体系冲突，未自动分配”；
- 输出到 Excel 的“颜色体系待处理”Sheet，等待人工建立体系级归并规则。

建议逐步给 `面料颜色归并对照` 补充 `颜色体系` 字段值，以解决跨体系同码的库存归属。

可选迁移语句：

```sql
ALTER TABLE `面料颜色归并对照`
ADD COLUMN `颜色体系` VARCHAR(30) NOT NULL DEFAULT '' AFTER `面料编号`;
```

迁移后，优先维护 A2023/B2024 的体系级规则；旧规则仍可保留为空体系作为兼容兜底。
