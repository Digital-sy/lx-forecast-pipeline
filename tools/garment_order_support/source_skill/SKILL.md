# 下单表文件查询与版本证据

先查文件和来源，再解释内容。把“找到文件”“已读原文”“确认用料方案”分开。

## 选择入口

- **查已有款号/订单**：优先查询已封存索引，明确其来源日期。使用 `scripts/order_index.py query`；SPU与订单号精确匹配，材料/颜色只是文本检索，不能视作映射确认。
- **查当前文件或准备补充**：先读本机 `lark-shared` 与 `lark-drive` 的 files-list 说明，核对实际CLI版本/schema，再用 `scripts/discover_order_files.py` 在用户明确的根目录下有界枚举。默认只生成计划；`--execute-read` 才进行远端只读查询。不得把目录清单当附件内容已取得。
- **识别新增/修改**：用 `scripts/plan_refresh.py` 比较两个来源清单。修改时间或内容变化必须重新核验；已下载的token不是跳过依据。只有完整且同范围的清单才能判断来源缺失；不删除旧档。
- **读取原件**：上传附件由 `feishu-file-review` 获取；在线表格由 `lark-drive` 支持的导出取得。每个新版本单独封存。布局确认后，用本技能已锁定的 `scripts/read_order_cells.py` 读取指定单元格。它保存原值/公式/合并定位，不计算公式、不看图、不解释材料。
- **逐色判定**：将查到的文件和证据交给 `$garment-order-color-evidence`，继续面料、部位、实物色号及目录候选核验。人工结果独立保存。

## 本地索引建立

新工作放 `E:/CodexWork/Tasks/<task>`，历史原件、历史索引和人工表只读。源码目录不存业务数据或凭据。

`order_index.py build --config <config.json> --output-dir <新目录>`

配置读取既有 inventory、下载日志、文件解析审计和订单行，可同时接入深化证据、人工确认和订单状态快照。字段见 [输入与版本合同](references/source-contract.md)。默认重新核对原件SHA；未核验、原件丢失或版本不符不能称已验证证据。索引保存来源时间，不用建索引时间冒充业务日期。

`order_index.py query --index <索引目录> --spu <款号> --output-dir <新目录>`

也可使用 `--order-id`、`--material`、`--color`、`--market`、`--source-id`；`--file-name` 仅提供文件名线索。至少一个条件，多个维度同时满足。同SPU跨店不自动通用，market不是精确shop。返回完整候选，不取最新文件或第一条定稿。大结果按明确limit报告截断，不把截断数当总数。 颜色检索仅覆盖已结构化的原颜色/色码、颜色候选、实物号及目录候选，材料检索覆盖已提取的材料字段；不是工作簿全文搜索。共享备注或图片中的文字需回到原件另查。

## 版本和语义规则

- 来源文件ID、内容SHA、业务订单号与单元格位置分别保存。相同内容多个来源保留别名；行号不是跨版本稳定业务主键。
- 本地索引由已归档版本建立，不代表飞书当前版本已核验。发现源修订后保留旧版和新差异，不覆盖旧人工确认。
- 附件修改时间、获取时间、解析时间、正文日期、状态获取时间分开；缺失保留未知。
- 取消、返修、尾数及冲突作为事实保留。未来默认方案的有效性在业务判定阶段处理。
- 日期冲突、同订单不同内容、SKU/SPU冲突、缺号和多候选不得通过取第一条解决。
- 未知不是0；历史订单数量不是未来预计下单量。这里不重算预测、用量、库存或采购。
- 输入或输出校验失败时保留失败包，不以旧成功文件冒充当前成功。全部命令拒绝覆盖已有输出目录。

## 验收与边界

按 [运行与验证](references/runbook.md) 使用。目录枚举、文件下载、表格解析、业务确认分别报告；真实远端调用和合成测试分别记录。

本技能当前交付查询代码、索引、差异规划与定位读取。没有自动下载执行器或定期调度，也没有自动判定全部新文件布局、图像色号或未来方案。后续数据库建表须基于实测字段合同另做设计与实施，不能因本技能安装就宣称数据源已上线。
