# 追加与参数化增量能力

本文是此前公开进度的后续增量，旧 README、进度文件和发布清单保留其历史含义。最新新增文件由 `release_manifest_incremental_v2.json` 单独列明。

## 已完成

- 追加核心已完成隔离验证，并在获准范围完成一次实际追加及独立回读；私人执行回执与业务数据不随源码发布。旧记录和审计时间保持不变，同键冲突不会自动覆盖。
- 规划器可以对照已归档索引和已验证的数据库快照，生成取件、内容修订、未解析、证据复核、追加缺口和远端核验队列。它不会自行获取文件、连接数据库或启动任务，也不会把历史归档当作当前远端状态。
- 本地解析入口接受显式文件范围、下载回执及解析器/依赖哈希。默认仅检查；只有显式 `--execute-local-parse` 才调用已审查并固定版本的本地解析器。输出写入新目录，拒绝覆盖；原件和人工确认不修改。
- 人工确认、文件版本匹配和未来默认方案属于不同状态。版本变化进入复核队列，不自动清空已有业务确认或升级方案。

## 验证与运行边界

公开包只包含可复用核心与合成测试，不包含真实解析器、私有依赖路径、业务配置、业务明细、实例身份或认证信息。依赖 manifest 应在受控环境独立维护，固定解析器与其 helper 的真实路径及哈希。哈希校验只能确认选择的版本，不能替代对依赖行为的审查；该入口不是任意代码沙箱。

在 `acquisition` 目录运行新增合成测试前，将进程级 `GARMENT_INCREMENT_TEST_TMP` 设置为独立测试目录，再运行：

```text
python -B -m unittest discover -s tests -p test_incremental_refresh.py -v
```

该测试使用生成的合成文件和合成解析器，不读取真实业务文件，不连接服务。脚本参数用 `python -B scripts/plan_incremental_refresh.py --help` 和 `python -B scripts/parse_incremental_refresh.py --help` 查看。追加核心的合同与测试命令见 `database/APPEND_README.md`。

## 尚未启用

自动调度仍未启用。规划和解析能力不等于周期性刷新已经运行，也不自动执行数据库追加。远端当前目录观测、显式获取清单、每版材料解释及人工确认范围、装载包验证和独立回读仍需在受控流程中逐步完成。私有布局解析依赖仍需审查，没有宣称已经成为通用于所有下单表的解析器。

不据本次证据追加直接修改飞书结果、采购建议或看板；自动采用未来面料方案和颜色映射仍需明确业务确认。
