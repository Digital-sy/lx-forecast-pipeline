# 成衣下单表支撑数据源

本目录保存可复用的脱敏代码、数据合同和阶段进度。它用于先建立下单表证据源，再支撑面料、部位、实物色号与领星候选的核对；解析候选不等于已经批准的业务映射。

## 当前交付

| 模块 | 用途 | 执行边界 |
| --- | --- | --- |
| `source_skill/` | 有界文件发现、版本索引、增量计划、按款号/订单查询、明确单元格读取 | 默认只读；不建表、不自动确认颜色 |
| `acquisition/` | 按显式清单获取新增或修订的下单文件 | 最多15文件/30次CLI调用；默认检查，显式执行才远端读取 |
| `database/` | 本地装载包构建、九表DDL、首次装载与独立回读核心 | 连接由受控调用方提供；没有公开的生产连接入口 |
| `docs/progress.md` | 已执行、未完成与后续边界 | 历史执行回执摘要，不代替实时系统检查 |
| `release_manifest.json` | 本次公开文件哈希、源版本与验证范围 | 不包含业务输入及认证信息 |

原件 → 文件身份/内容版本 → 观测与解析批次 → 原始逐色证据 → 材料/部位解释 → 人工确认引用。

目前首次入库止于原始逐色证据；材料解释与人工确认表已建，但尚未迁入旧结果。它不是采购订单事实表、最终颜色字典或自动面料需求计算链。

## 本地验证

使用已有 Python 3.12 环境，不必连接数据库或飞书。标准库测试可分别在各模块根目录运行：

```text
python -B -m unittest discover -s tests -v
```

运行 `source_skill` 测试前，把进程级 `ORDER_SOURCE_TEST_ROOT`、`GARMENT_SOURCE_TEST_TMP` 指向独立临时目录；运行 `acquisition` 测试前设置 `FETCH_INCREMENT_TEST_ROOT`。不要设置为真实归档目录。数据库模块本次测试使用合成连接对象，不读取配置、不创建数据库。

文件索引与计划仅依赖标准库；实际工作簿读取使用已核验环境中的 openpyxl / xlrd。数据库实际连接使用 PyMySQL；本提交不安装依赖、不改变生产环境。原真实 MySQL 验证与本次离线复测分别记录。

技能命令、文件合同见 `source_skill/SKILL.md` 与 `source_skill/references/`。获取器及装载包构建器先用 `--help` 核对参数。`mysql_load_core`、`schema_ops` 是供受控调用的库，不会在导入时连接服务。

SQL公开副本仅移除部署位置与内部文档指纹注释，DDL语句保持不变。对应库文件绑定公开SQL的新哈希，原生产工件和原装载包保持原哈希；不要把不同版本的包混用。此次GitHub同步不再次建表、装载、部署或开启调度。

`source_skill/release_manifest.json`保留原技能发布记录（当时未提交远程），本次公开同步文件清单以顶层`release_manifest.json`为准。装载包构建器仍遵循既有私有归档布局，不支持任意目录直接装载。
